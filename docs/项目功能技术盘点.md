# 项目功能与技术盘点

## 项目定位

当前项目是一个面向小学英语单词学习的静态前端应用，核心能力集中在单词浏览、打字练习、Excel 导入和学习记录分析。

主入口文件为 `enhanced-word-tool.html`，现已拆分为：

- `enhanced-word-tool.html`
- `assets/css/enhanced-word-tool.css`
- `assets/js/enhanced-word-tool.js`

## 当前已实现功能

### 1. 学习入口与配置

- 支持选择年级
- 支持选择难度
- 支持配置单词数量
- 支持配置学习时长
- 支持进入卡片学习或直接开始游戏

### 2. 单词库管理

- 内置默认单词库
- 支持上传自定义 Excel 单词库
- 支持切换回默认单词库
- 支持下载 Excel 模板

Excel 使用 34 列正式模板，必填字段和枚举值见
`docs/Excel导入规范.md`。

### 3. 卡片学习

- 单词图片展示
- 中英文展示
- 记忆方法展示
- 单词发音
- 卡片翻转
- 上一个 / 下一个切换
- 支持键盘左右键切换
- 支持自定义单词图片

### 4. 主动回忆挑战

- 看图选英文、听音选英文、中英互选
- 字母拖拽、半提示拼写、短语排序和语境填空
- 自动朗读当前单词
- 提示系统
- 分数统计
- 计时器与时间进度条
- 完成进度条
- 已完成单词列表
- 结束页成绩反馈

### 5. 学习数据分析

- 总学习次数
- 累计学习单词数
- 平均正确率
- 各年级掌握情况
- 最近学习记录
- 首次答错单词统计
- 高频错误单词统计

## 当前技术情况

### 技术栈

- HTML 单页应用
- Tailwind CSS CDN
- Font Awesome CDN
- SheetJS / XLSX CDN
- 原生 JavaScript
- Web Speech API
- localStorage

### 工程形态

- 使用轻量 `package.json` 管理检查命令
- 无构建工具
- 无模块化打包
- 词库、导入、游戏和统计核心已模块化
- 使用 Node.js 内置测试运行核心流程测试
- 无后端服务
- 无接口层
- 当前目录不是 Git 仓库

### 数据存储方式

- 默认词库位于 `assets/js/modules/word-database.js`
- 学习记录存储在浏览器 `localStorage`
- 自定义 Excel 仅在当前浏览器会话中解析并使用

## 主要问题

### P0：直接影响可用性或结果准确性

- 默认首页下拉框存在空值初始化风险，可能导致首屏逻辑异常
- 原实现把“用户设置题量”和“实际出题题量”混在同一个变量里
- 历史累计学习单词数按当前题量估算，不按历史真实记录统计
- 记录正确率按当前配置题量计算，不按实际作答题量计算
- 高频错误单词原本按“低正确率整局”粗略统计，不是真实错误词

### P1：影响维护与扩展

- 页面、样式、逻辑原本全部写在一个 HTML 文件中，维护成本高
- 1–5 年级为三档基础覆盖词库；六年级为教材完整词库
- 目录里保留了多个历史 HTML 版本，容易混淆
- 项目缺少 README、启动说明和数据说明

### P2：产品化阶段会遇到的问题

- 依赖外部 CDN，弱网或离线环境下不可用
- 数据仅保存在浏览器本地，无法跨设备同步
- 没有用户体系，无法做班级、学生、教师视角管理
- 默认图片主要依赖外链随机图，稳定性一般

## 建议优先级

### 第一阶段：先保证稳定可用

- 补齐默认年级 / 难度的基础数据
- 保持统计口径统一
- 增加 README 和数据格式说明
- 清理历史版本文件，明确主入口

### 第二阶段：提升可维护性

- 继续拆分数据、视图、分析逻辑
- 把默认词库单独抽成 JSON 或 JS 数据文件
- 为关键流程补最基础的手工测试清单

### 第三阶段：产品化升级

- 引入构建工具
- 增加后端与账号体系
- 支持云端词库与学习记录
- 增加教师端 / 家长端 / 学生端视角
